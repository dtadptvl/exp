# Global Prime / disposable sub (Kilo CLI)

Windows: double-click `setup.cmd` (Kilo installed). To update an existing installation whose original agents are already backed up, run `powershell -File install.ps1 -UpgradeOwned` after confirming the two installed agents are this package's; it saves a revision snapshot and preserves original-agent backups. Do not use this flag on a manually edited agent. `AI_CONFIG_MERGE_GUIDE.md` is **for a web chatbot**: paste the guide plus a copy of your existing config with secrets redacted; the chatbot returns a minimally edited config or a safe patch. Back up the original and restore secrets locally; the installer never edits config. Then verify locally with `kilo debug agent prime` and `kilo debug agent sub`. Run in any Git project with `kilo run --auto --agent prime "your request"`. For a silent request, configure provider timeouts as described in `AI_CONFIG_MERGE_GUIDE.md`; if a whole Sub/task stalls, manually cancel its native Kilo session and replan from Git/state. Provider request timeout is **not** a whole-worker deadline. No promise of unattended quality without real provider access. Uninstall: `powershell -File install.ps1 -Uninstall`. Package has no runtime dependency on reference ZIP.

Installer places ONE `state.py` next to the global agents and embeds its absolute path in installed `prime.md`. It does **not** copy the script into projects. Run Kilo from the Git project root: Prime calls this global script there; `refresh` prints a small packet, `ack` acknowledges reviewed Git delta and creates that project's `.prime/state.json` on first use, `check` exits 1 on divergence. If Python or the installed script is missing, fix installation; do not silently skip state. Markers fingerprint only dirty files (including staged state): unchanged dirty files do not generate repeated invalidation. Snapshot acknowledges observed bytes, not ownership; Prime still checks human edits before writing. Prime writes the objective and active contract into each project's `.prime/state.json` before delegation; `ack` alone only initializes an empty objective. Sub never edits state. `tasks` maps IDs to `{status,produces:[paths],consumes:[paths],depends_on:[IDs],verified_by:[IDs],assumes:[IDs],evidence:[refs]}`. `active` names the task; store the task contract there or under its ID. `git` is branch, HEAD and porcelain status, not a history duplicate. Git is source of code truth. Reconcile at every human prompt and after Sub return. `ack` does not resolve semantic assumptions automatically: Prime assesses which affected edges remain valid and rechecks only affected successors. If unrelated unknown paths changed, inspect before acknowledging.

Native Kilo owns agent discovery, child sessions, compaction, Task execution and permissions. A 30-minute `chunkTimeout` only applies to supported provider HTTP streaming; it cannot terminate a stalled tool or an endless series of requests. Retry at most once per unchanged failure signature before explicit replan; never overwrite human files. Serial workers by default: shared tree prevents safe concurrent writes without coordination.

Smoke on Kilo 7.8.1: Prime delegated one read-only task to `sub` on `9router/sub`, received the first line and exited 0; no edits. Timeout behavior after 30 minutes was not tested.

Contract keys: `task_id, objective, in_scope, out_of_scope, acceptance, hard_constraints, relevant_files_symbols, dependencies, verification, stop_condition`. Sub returns `task_id,status,summary,files_changed,verification,evidence,risks,out_of_scope_findings,next_required_action`. Test: `python tests/check.py`. No package dependencies beyond Python stdlib, Git, PowerShell and Kilo CLI.
