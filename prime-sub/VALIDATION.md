# Validation and limits (Kilo CLI 7.8.1, Windows)

Source: official `kilo-org/kilo` config/agent/task/run code and local `kilo debug` (2026-09-21). Global `{agent,agents}/**/*.md` filename is the agent name; use lowercase `prime` / `sub`. `prime` primary; `sub` subagent, model from agent Markdown. Task filters non-primary agents by caller Task permission, launches child session, cancels on parent abort. Native sessions/compaction persist, but not a cross-session objective/DAG. `kilo run --auto --format json` supports unattended execution and event stream. Local effective config has `default_agent=prime`, `subagent_depth=1`; upstream config source did not contain a `subagent_depth` schema field: **depth enforcement is unproven**. `sub` denies Task; built-ins not modified. Agent permissions and config merges have precedence: check effective config locally, especially project overrides. Provider `chunkTimeout: 1800000` is available in the local effective `9router` options; upstream config allows extra provider options but source inspected does not implement a universal whole-Sub timer. Native `timeout` applies per request; chunk timeout effectiveness depends on the provider SDK. Neither can bound tools or repeated requests. Hooks/plugins/MCP are deliberately untouched, not a watchdog.

Reference audit (references not imported into runtime): current extracted 20260921 nomemory package: global agent policies and backup installer useful; discarded `steps:64` fuse; retained the optional provider `chunkTimeout` concept for silent streaming (not as a whole-task stall control), replaced prompt-only state with stdlib checkpoint. `kilo-prime-sub-redesign.zip`: contracts/DAG/receipt and scenario examples useful; discarded schemas, journal, validation framework and fixed role taxonomy. `prime-sub-git-native-fixed.zip`: Git truth and bootstrap useful; discarded wrapper and worktree-oriented control. `prime-sub-3tier-routing.zip`: adaptive routing idea useful; discarded tier/persona routing. Older `prime-sub-minimal-adaptive*.zip` archives: near-duplicate policy and tests, no separate runtime dependence; earlier prompts rely on `steps`, no real stalled-process termination. `prime-sub-pi.zip`: pi extension implementation is platform-incompatible; no pi runtime port. None of these is trusted as a current Kilo spec.

Earlier watchdog experiment exited 124 during a real Prime run; the watchdog and its idle-kill test have now been removed at user request. Executed: `python tests/check.py` PASS (selective dependency closure, Git change, restart state); `python -m py_compile` PASS; `install.ps1` install/reinstall/uninstall/reinstall PASS; `kilo debug agent prime/sub` effective primary/subagent and `9router/sub` PASS. Real `kilo run --auto --agent prime --format json` attempted on a README inspection: one Task completed with child metadata `9router/sub`, but watchdog exited 124 after inactivity; **that earlier task did not complete**. After removing the watchdog, a new real `kilo run --auto --agent prime --format json` exited 0: the Task tool completed using `9router/sub`, Prime returned the verified first line `# experimental`, and Git showed no project edit. This is one read-only smoke, not coding-quality E2E or proof that a 30-minute chunk deadline fires. No validated failure retry, no live compaction/retroactive repair, no 20–50-case eval or baseline comparison. Do not call this production-ready.

Known limits: provider timeouts cannot guarantee detection or termination of a whole stalled Sub. Without an external deadline this architecture does **not** meet the original automatic stall-kill invariant; manual Kilo cancellation is the fallback. `state.py` maps path edges and transitive task IDs but semantic invalidation/repair and verified_by/assumes edges require Prime judgment. Untracked deletion/rename, Git index state and human/worker attribution are not robustly modeled. Dirty paths remain in refresh after acknowledgment intentionally; inspect marker rather than claiming a clean tree. Path checkpoint is small, but not an exact content hash. Concurrent write scheduling is intentionally serial. Model cost/token metrics unavailable; not fabricated. A follow-up read-only smoke used the previously installed agents (the edited prompts were NOT installed): Prime→sub completed with 7 tool results, compared with 2 in the earlier different-wording smoke, and Prime reread the file. This is neither a valid optimized-prompt comparison nor evidence of token/time savings. Install edited prompts and compare identical tasks before claiming gains. Updated prompts installed via `-UpgradeOwned`; a new README first-line smoke exited 0 with one Prime Task tool result (no Prime read), child model `9router/sub`, no edits. The earlier smoke used a differently worded instruction, so its two tool results vs one are not controlled cost evidence; token counters include cache/accounting artifacts and do not establish savings. No coding-quality claim from this read-only task. One separate coding E2E in a disposable Git fixture also exited 0: Prime delegated one `slug.py` bug fix to `sub` (`9router/sub`), changed only `slug.py`, `python -m pytest -q test_slug.py` passed (1 test), targeted diff passed, Prime returned the patch/check outcome. Fixture created an untracked `__pycache__/`; no broad eval, repeated baseline, or reliable token/time improvement measured. Eval rubric when access exists: correctness, regression, unauthorized files/scope, premature/post-success edits, delegation necessity, objective retention, verification evidence, retries, Prime tokens/tools, elapsed time. Baseline and optimized runs should repeat nondeterministic tasks; classify goal/instruction drift, scope creep, overthinking, bad delegation/context/verification, stale state and impact failure before changing prompts.

Rejected: DB, daemon, plugin, custom session manager, graph framework, worktrees, step-limit watchdog; do not claim that provider timeout replaces whole-worker supervision. Add narrower child supervision only if automatic termination is again required. State refresh is a handful of keys plus active task and Git delta; token count not measured.
