# Validation and limits (Kilo CLI 7.8.1, Windows)

Source: official `kilo-org/kilo` config/agent/task/run code and local `kilo debug` (2026-09-21). Global `{agent,agents}/**/*.md` filename is the agent name; use lowercase `prime` / `sub`. `prime` primary; `sub` subagent, model from agent Markdown. Task filters non-primary agents by caller Task permission, launches child session, cancels on parent abort. Native sessions/compaction persist, but not a cross-session objective/DAG. `kilo run --auto --format json` supports unattended execution and event stream. Local effective config has `default_agent=prime`, `subagent_depth=1`; upstream config source did not contain a `subagent_depth` schema field: **depth enforcement is unproven**. `sub` denies Task; built-ins not modified. Agent permissions and config merges have precedence: check effective config locally, especially project overrides. No claim that a provider chunk timeout bounds all in-flight child stalls. Hooks/plugins/MCP are deliberately untouched, not a watchdog.

Reference audit (references not imported into runtime): current extracted 20260921 nomemory package: global agent policies and backup installer useful; discarded `steps:64` fuse and provider `chunkTimeout` as primary stall mechanism, replaced prompt-only state with stdlib checkpoint. `kilo-prime-sub-redesign.zip`: contracts/DAG/receipt and scenario examples useful; discarded schemas, journal, validation framework and fixed role taxonomy. `prime-sub-git-native-fixed.zip`: Git truth and bootstrap useful; discarded wrapper and worktree-oriented control. `prime-sub-3tier-routing.zip`: adaptive routing idea useful; discarded tier/persona routing. Older `prime-sub-minimal-adaptive*.zip` archives: near-duplicate policy and tests, no separate runtime dependence; earlier prompts rely on `steps`, no real stalled-process termination. `prime-sub-pi.zip`: pi extension implementation is platform-incompatible; no pi runtime port. None of these is trusted as a current Kilo spec.

Executed: `python tests/check.py` PASS (selective dependency closure, Git change, restart state and subprocess idle kill); `python -m py_compile` PASS; `install.ps1` install/reinstall/uninstall/reinstall PASS; `kilo debug agent prime/sub` effective primary/subagent and `9router/sub` PASS. Real `kilo run --auto --agent prime --format json` attempted on a README inspection: one Task completed with child metadata `9router/sub`, but watchdog exited 124 after inactivity; **overall task did not complete**. No full Prime→Sub→verified acceptance success, no validated failure retry, no live compaction/retroactive repair, no 20–50-case eval or baseline comparison. Do not call this production-ready.

Known limits: watchdog watches completed tool events, not semantic diff/test deltas; it supervises the *whole CLI process*, not just a child Task. `state.py` maps path edges and transitive task IDs but semantic invalidation/repair and verified_by/assumes edges require Prime judgment. Untracked deletion/rename, Git index state and human/worker attribution are not robustly modeled. Dirty paths remain in refresh after acknowledgment intentionally; inspect marker rather than claiming a clean tree. Path checkpoint is small, but not an exact content hash. Concurrent write scheduling is intentionally serial. Model cost/token metrics unavailable; not fabricated. Eval rubric when access exists: correctness, regression, unauthorized files/scope, premature/post-success edits, delegation necessity, objective retention, verification evidence, retries, Prime tokens/tools, elapsed time. Baseline and optimized runs should repeat nondeterministic tasks; classify goal/instruction drift, scope creep, overthinking, bad delegation/context/verification, stale state and impact failure before changing prompts.

Rejected: DB, daemon, plugin, custom session manager, graph framework, worktrees, step-limit watchdog; native Kilo or small stdlib code covers the observed boundary. Add narrower child supervision and stronger Git markers only after reproducible failure. State refresh is a handful of keys plus active task and Git delta; token count not measured.
